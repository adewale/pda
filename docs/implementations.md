## Historical survey — 11–18 October

Every public implementation of [Poppy, the Personal Agent Protocol](https://personalagentprotocol.org/) (Draft 0.1) we could find, surveyed on **11 October 2026**, twice on **12 October 2026** (a second pass that evening) and again on **18 October 2026**, with the grid's pins rechecked on **13 October**. Sierra and Meta announced it on 7 October and published the draft on 9 October, so everything listed is at most a few days old. The whole ecosystem around them (the spec, checkers, demo Companies, adjacent projects, and how they work together) is mapped in [ecosystem.md](ecosystem.md).

**12 October.** We rechecked every row: new commits and releases, archived repositories, Sierra's GitHub organisation, the spec site (`node scripts/spec-snapshot.mjs`: no text changes), and the same GitHub, npm, PyPI, crates.io and web searches, for anything created since 5 October. We fetched no `poppy.json` that day. New hosts come from public directories, and say so. We read each new repository at a pinned commit, and ran two validators only in a container with no network ([the cross-check](interop-testing.md#validator-cross-check)).

**12 October, evening.** The spec site again (`node scripts/spec-snapshot.mjs`: no body or text changes), and still no public source repository for it. `git ls-remote` of every upstream our grid pins, with the GitHub compare API for the ones that moved ([interop-testing.md](interop-testing.md#candidates-from-the-12-october-survey) says what moved and which pins to move). The same searches for anything created on 12 October, plus PAP Checker's directory and the two community lists. This time we ran our validator CLI (`npm run validate -- <domain>`) once against each live Company we know of, one host at a time, a few seconds apart: it fetches the `poppy.json`, following redirects, and the issuer's OAuth metadata, and nothing else ([verdicts below](#live-companies-checked-on-12-october)). New repositories were downloaded at their head into empty directories and read; none was run.

**13 October, morning.** Pins only: `git ls-remote` of every upstream the grid pins, each diff since our pin read in a fresh directory, and the pins moved to each head ([interop-testing.md](interop-testing.md#pins-moved-on-13-october)). Datalayer reached 0.17.0, print-with-poppy opened a hosted Agent Sandbox, Ilmer's agent gained web tools, adonis-agora and everruns changed nothing in their Poppy code, and Tipping Co (timothyohare) joined the grid on both sides. Nothing else was searched or fetched, so the rest of this page is as of the evening of 12 October.

**18 October.** Everything again, read-only: the spec site (`node scripts/spec-snapshot.mjs`, which found **Draft 0.2 in progress**, stored as [spec/draft-0.2-retrieved-2026-10-18](https://github.com/adewale/pda/blob/052557f042ed666d42190c7ca0c7b2fece2bed8d/spec/draft-0.2-retrieved-2026-10-18/README.md)), the spec's new public repository and its issues, Sierra's organisation, `git ls-remote` of every row's repository with each move read in a blobless clone in a fresh directory, npm and PyPI, web search for anything new since 12 October, the two community lists, PAP Checker's directory and the spec's implementation reports. GitHub was read through git and its public pages, not its API. Our validator CLI ran once against each live Company we know of, one host at a time ([verdicts](#live-companies-checked-on-18-october)). Nothing was run but our own validator; the grid's pins didn't move. What 0.2 changes is in [the upgrade delta](poppy-0.2-upgrade.md).

**11 October method.** Read-only. GitHub search for repositories, code (`well-known/poppy`, `personalagentprotocol`, `poppy_domains`, `poppy:write`, `browser_session_endpoint`, `PoppyClient`, `poppy-client`, `poppy-agent`, "Personal Agent Protocol"), issues and pull requests created since 1 October; npm, PyPI and crates.io; web search; the two community lists ([awesome-poppy](https://github.com/JaviChulvi/awesome-poppy), [poppy.md/implementations](https://poppy.md/implementations)). One `GET /.well-known/poppy.json` per domain: a bare-domain redirect to `www.` was followed once. Documents that came back were checked offline with our validator (`npm run validate -- --kind poppy --domain <d> <file>`). That checks only the document itself, not the issuer's OAuth metadata. Nothing was posted, starred or forked.

## What we can learn from the 12 October participants

Each lesson names the change it suggests; the ones marked **decision** are the owner's. Several were made the same day, most under [decision 24](decisions.md#24-conformance-levels-from-each-requirements-basis) (the conformance levels). Where a lesson has a **Status**, it says what was done, and the last column of the [cross-check table](interop-testing.md#validator-cross-check) does the same for each validator rule.

1. **Say each message's basis.** poppy-validator gives every rule a basis (MUST, field table, advisory, context), and `--strict` fails only advisory findings. Our mock's checks already name theirs (`test/mock-company/violations.ts`); our validator's messages don't. Add a `basis` to each entry in `src/validator/messages.ts`, show it in the report and the CLI, and let `--strict` follow it. **Status:** done; every message has a `basis`, and `poppy-validate --strict` fails on warnings.
2. **Check the host in every URL.** poppy-validator refuses `https://.` as `auth.issuer`; ours accepts it. `httpsUrl` in `src/validator/primitives.ts` should require a host name or an IP literal, with a fixture in `test/validator.test.ts`. **Status:** fixed; it is an error.
3. **Severity by declared version.** The draft says each API's `type` "MUST be one of" `openapi` and `mcp`, and that anyone else's extension MUST have a domain prefix. poppy-validator makes both errors in a 0.1 document and info in a newer minor, which may define them; we report info and a warning whatever the version. Pass the declared minor to `checkApis` and `checkExtensions` in `src/validator/profiles/draft-0.ts` and do the same. **Status:** done for API types, an error at a minor version we know; a plain extension name is still a warning, kept as a reading.
4. **Don't be stricter than the text where it's cosmetic.** An integer extension `version` is an error for us and fine for them; the draft states no type ([N22](spec-issues.md#n22)). Make it a warning. **Status:** done.
5. **Field-table members.** poppy-validator errors on an `apis` entry without `description`, an empty `agent.protocols` and a missing `organization.name`, reading the field table as required; we warn ([S18](spec-issues.md#s18)). **Decision:** follow the field table, or keep warning because agents work either way. **Status:** a missing `description` and a missing `organization.name` are now errors; an empty `agent.protocols` is still a warning.
6. **A byte order mark.** RFC 8259 says senders MUST NOT add one; both Python validators fail to parse it, and we warn. **Decision:** make `json-bom` an error. **Status:** done.
7. **Diagnose a misplaced metadata document.** When the issuer has a path and its metadata isn't at the RFC 8414 location, poppy-validator also tries the appended location and says it found it there (`OA09`), still failing the check. Our validator could do the same as a diagnostic, never our client ([S3](spec-issues.md#s3)).
8. **Keep the cross-check.** Their 51 fixtures (MIT) and ours, run through both validators, found one gap in ours and several readings. **Decision:** commit the cross-check as a small script beside `interop/vectors/datalayer/`, fetching their fixtures at a pinned commit and running their code only in Docker, or leave it as the one-off in [interop-testing.md](interop-testing.md#validator-cross-check). **Status:** committed as [`interop/vectors/validators/`](interop-spec.md#14-retired-with-01-and-02).
9. **Move the Datalayer pin.** 0.10.0 accepts all three client assertion `aud`s, so adonis-agora's S1 failures at both Datalayer Companies should pass, and a known failure that no longer fails makes the run fail. **Decision:** bump `interop/registry.json` to `0c048aa`, rebuild the two Datalayer images, and update `interop/known-failures.json`. **Status:** done on 12 October. The pin, the four adapters and the known failures' links moved, and the rebuilt images' full grid changed 12 cells. Among them, adonis-agora's S1 cells at both Datalayer Companies now pass, and pi-poppy's two O known failures were stale and are gone ([results](interop-results/README.md)).
10. **Path issuers are coming.** Fillthemat plans one issuer per School under a path on a shared host, with RFC 8414 insertion, which is what our `DP` scenario tests. It reads S1 as "exactly this School's token endpoint"; if it means that at the revocation endpoint too, it would refuse our assertions there. Add it to the S1 evidence when its code lands, and run `DP` against it.
11. **A store that needs Operations for every order.** print-with-poppy requires Operations v1 to order, and a guest order is an operation proposed in a signed-out Session ([N19](spec-issues.md#n19)), its normal path. It is in the grid for D, S0, CM and OU (OU with pda only), the signed-out Operations scenario written for it: a `multipart/form-data` photo upload, then an order that proposes an operation, approved and confirmed ([interop-testing.md](interop-testing.md#candidates-from-the-12-october-survey)). Since its accounts (`260dbb4`, 12 Oct) the grid runs its sign-in too: SD, SX, SMC, SO, AO, AS and R.
12. **Watch the directories.** PAP Checker's directory listed three hosts we hadn't seen. Read it in each survey, without fetching the hosts ([ecosystem.md](ecosystem.md#how-to-update-this-map)).

From the evening pass:

13. **A path issuer is live.** Emora Health's issuer is `https://www.emorahealth.com/poppy`, with its metadata only at the RFC 8414 inserted location. It is the first live evidence for [S3](spec-issues.md#s3): agents that append the well-known segment (everruns, pi-poppy, poppy-demo's caller) can't use it, and our client, which inserts, can. S3's row now cites it.

A hosted provider is how most small businesses will appear, so a redirect to another host is the normal case for discovery, not an edge case.

## What we can learn from the 18 October survey

18. **0.2 is coming, and S1 goes against us.** Draft 0.2, in progress, makes both assertions name the issuer and has Companies refuse any other `aud`. Our agent names the endpoint it calls, as [readings.md](readings.md) records. When 0.2 is published, or a Company we meet requires the issuer (Ample Computer already does), our client, both mocks' S1 settings and the S1 rows of [spec-issues.md](spec-issues.md#s1) and the fault lines in [ecosystem.md](ecosystem.md#open-fault-lines) need to move. **Decision**, the owner's: when to send the issuer, and whether to send it to a Company that declares 0.1.
19. **The domain rule changes the validator.** 0.2 compares `organization.domain` with the host that served the document after redirects, not the host requested, and counts `www.`. By that rule Ample Computer, invalid by 0.1, is right, and three live hosts are wrong. Our validator should check a document by the version it declares, with this as a fixture for each.
20. **Two new validators to cross-check.** The spec's own kit validator, with an offline mode, and Poppy Check are open; both would fit [`interop/vectors/validators/`](interop-spec.md#14-retired-with-01-and-02).
21. **New grid candidates.** poppy-gateway (a Company claiming sections 3 to 7) first, then poppy-agent-demo (an agent with Device Sign-In); Cobus Greyling's demo serves only HTTP. Adapters would fetch them at a pinned commit, as for the others ([interop-testing.md](interop-testing.md)).
22. **Pins to move.** Seven of the grid's ten upstreams moved; only print-with-poppy's revocation change touches a known failure. adonis-agora 0.81 needs Node 24, so its agent adapter's image has to move with the pin.
