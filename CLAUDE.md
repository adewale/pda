# Poppy Demo Agent

The design is `pda-spec.md`; read it before changing anything. Why it is built that way is `docs/decisions.md`; what's left to deploy and check is `docs/deployment-tasks.md`; how a person uses it is `docs/using.md`. Built: one Worker with its own Google and GitHub sign-in (not Cloudflare Access), one `PersonalAgent` Durable Object per signed-in identity running Pi through `PiHarness`, and Claude Sonnet 5.5 through AI Gateway on the operator-paid demo lane, or the person's own Anthropic or OpenAI API key. Built beside Poppy: general tools (`read_url`, which renders pages that need JavaScript in Cloudflare Browser Run, memory, time and maths), and reminders and scheduled tasks on the Durable Object's alarm, with Web Push. Not built: skills (milestone 2). The Poppy (Personal Agent Protocol) client is in `src/poppy/`; Appendix A of the spec maps every requirement to the code and the check that covers it.

- `src/protocol.ts`, `src/sockets.ts`, `src/view.ts` and `src/transcript.ts` are copied unchanged from Cloudflare's Pi example (`cloudflare/agents`, `examples/next/harnesses/pi`, commit `48d9c36`). Do not edit them; re-sync them from upstream instead.
- Our code: `src/index.ts` (Worker routes), `src/oauth.ts` (Google and GitHub sign-in; `SIGNIN_PROVIDERS` says which a deployment offers, and `/api/sign-in-options` tells the page), `src/session.ts` (signed session cookie, agent naming), `src/allowlist.ts` (`OWNERS`, `SIGNIN_ALLOWLIST`, `DEMO_ALLOWLIST`, `SIGNUP`), `src/deployment.ts` (the vars a deployer must set; the Worker and `scripts/check-deployment.ts` check them), `src/model-router.ts` (the lane for each model call: own key, demo with caps, or none), `src/compaction.ts` (the context budget and our summarizer on pi-durable's compaction hook), `src/history.ts` (the page's messages from before a summary), `src/attachments.ts` (the User's photos, in the agent's SQLite; `src/attachment-images.ts` shows them to the model and deletes them after 30 days (`AttachmentExpiry`, a Lifecycle job), `src/ui/attachments.tsx` attaches and shows them), `src/model-keys.ts` (sealed own keys, key checks), `src/budget.ts` (demo spend ledger and the `DomainBudget` Durable Object), `src/config.ts` (vars and secrets, no defaults), `src/csp.ts` (the Content-Security-Policy on every page; `public/_headers` must match it), `src/base64url.ts` (the one base64url), `src/decode.ts` (decoders for whatever crosses into typed code; no casts at an edge) and `src/rows.ts` (each table's columns declared once; `rows()` and `one()` decode every row, and `test/rows.test.ts` checks the declarations against the schema), `src/log.ts` (the one logger: one wide event per request, turn, job and working page frame, JSON with the environment; its fields take only `Safe` values from its constructors, `literal`, `code`, `id`, `origin` and the rest, and free text only through `message`, which `redact`s it), `src/agent-log.ts` (the agent's side: `turn` events from pi's own events, the router's `onCall` and a wrapper on every tool; its newest 200 events in `agent_log` for Activity's "Copy diagnostics"), `src/agent.ts` (the Durable Object; it resets itself when pi's storage fails, and keeps no pi cache on a timer, decision 33), `src/poppy/` (the Poppy client, its Lifecycle capability and tools; correctness by construction, decision 31: `CheckedApiRequest.check` in `apis.ts` is the only way to make an API request and `outgoing.ts`'s `EndpointRequest` the only other thing `PoppyClient.resource` takes, `approvals.ts` stores approvals versioned and decodes them before sending, `signout.ts` revokes a signed-out account's token from `poppy_signouts`, retrying and telling the User when the Company refuses, `issuer.ts` makes every `Issuer` and `Origin`, `error-codes.ts` holds `PoppyErrorCode`, `frames.ts` the page's frames; `protocol-version.ts` names the one version it speaks, the reviewed 29 October text of 0.3 (decision 37: 0.1 and 0.2 are refused), and the pin it comes from; the Session header and delegated keys are `jwt.ts`'s `delegate` and `sessionJwt`, signed in `PoppyClient.resource`; Operations 2 is `operations-v2.ts`; task requests run before the Company's exact terms ask for approval (decision 38), while file uploads retain disclosure consent. `operations.ts` records task dispatch without a preliminary card, and `result-links.ts` gives the User returned HTTPS links without model transcription; task coverage, excluded tasks and feedback, is `coverage.ts`), `src/poppy/interop-client.ts` (a second, separate Poppy client for the live interop lane, served only when `INTEROP_LIVE_JWKS` is set; its private key stays on the runner's machine, made by `scripts/interop-live-identity.mjs`), `src/poppy/activity.ts` (the Activity frame, from the agent's own tables, never secrets), `src/poppy/protocol-log.ts` (each Poppy exchange per Company, whitelisted fields only; shown by `src/ui/protocol.tsx`), `src/poppy/fetch-browser.ts` (website browsing: plain HTTPS and `HTMLRewriter`, no JavaScript; `click` follows links only, a form goes only through an approved `submit`), `src/tools/` (the general tools as pi extensions in `extensions.ts`: `web.ts` for `read_url`, its own fetcher and never the Poppy one, and in `extensions.ts` its reader, a conversation owned by the call with no tools, the only one that sees the page (decision 34); `render.ts` for rendering a page that needs JavaScript in Browser Run (`allowBrowserRequest` lets only GET and HEAD to public hosts through, a fresh browser per render, 10 an hour per agent, `BROWSER_RUN` turns it off), behind the agent's `browserRenderer()` seam, which `test/fake-browser.ts` fakes; `memory-store.ts` for the `memories` table and its secret check; `clock.ts` and `calculate.ts`, pure, for `now`, `date_math` and `calculate`; `schedules.ts` for `remind_me`, `schedule_task`, `list_scheduled` and `cancel_scheduled`, refused in a turn the User didn't start, over `schedule-store.ts`, the `schedules` table and its zone-aware next runs; `docs/capabilities.md` lists every tool), `src/schedules.ts` (the `Scheduler` Lifecycle capability: one alarm job per active reminder or task; a reminder is a card and a push, a task a background turn), `src/web-push.ts` (Web Push in WebCrypto and `jose`: RFC 8291 encryption, VAPID, the push-service allowlist, `push_subscriptions`; `public/sw.js` shows the notifications), `src/ui/` (the page: shell and routing, chat, transcript, `tool-line.ts`, `history.ts` for summaries shown as notices, Activity, Companies, Settings, `memory.tsx`, `scheduled.tsx` and `notifications.tsx` for its Memory, Scheduled and Notifications sections, `model.tsx` for the key panel, demo meter and needs-key banner), `src/poppy-ui.tsx` (Poppy cards, the needs-you tray, receipts, the Direct Conversation sheet), `src/validator/` (the discovery document validator: no Worker APIs, so it also runs as the CLI in `scripts/poppy-validate.ts`, whose fetcher `scripts/node-fetcher.ts` refuses private addresses with `src/validator/address.ts`; a new message needs a fixture in `test/validator.test.ts`, whose last test checks every message has one).
- Poppy tests run against the strict mock Company in `test/mock-company/`; every Poppy test asserts it recorded no violations and no warnings. An `afterEach` enforces that; a test that breaks the protocol on purpose declares `expectViolations`. A new Poppy feature needs a test and, where the protocol states a requirement, a mock check with an id in `test/mock-company/violations.ts`, whose description starts with its basis (`MUST`, `RFC`, `Rule` for one stated without a keyword, `SHOULD`, `Guides`, `Reading`; `spec/grounding.md` quotes each), and a `TAMPERS` row in `test/mock-company.test.ts` (a catalog test enforces all three). The basis sets the level everywhere (`docs/conformance-levels.md`, `src/validator/levels.ts`): MUST, RFC and Rule are failures (mock violations, validator errors, cell failures); SHOULD, Guides and Reading are warnings, which only our own strict runs treat as failures. Validator messages carry a basis too, and their `refuses` flag (what our client refuses) is separate from severity. The page started as the example's; `src/client.tsx` now holds only the signed-out page and mounts `src/ui/`, and `src/use-pi-session.ts` folds the socket's frames.
- `interop/` is the M×N interop harness: a Node runner, a recording proxy, scenarios as data, and adapters for our agent (`interop/impls/pda-agent`, src/poppy in Node with node:sqlite, no model) and our mock Company (`interop/impls/pda-mock`, registered as the lenient reference `lenient-company` and as `strict-company`), with fakes on both sides: the agent adapter is also `lenient-personal-agent` (the reference agent), `strict-personal-agent` and `sloppy-personal-agent` (`INTEROP_AGENT_PROFILE`, `profiles.ts`; the sloppy one never live), and the mock also `evil-company` (`docs/interop-spec.md` §2.1). Third-party adapters and conformance vectors that still speak 0.1 or 0.2 remain retired (`docs/interop-spec.md` §14 retains their last pins). Our `evil-personal-agent` is restored as a 0.3 raw attack adapter, and NREP tests single-use authorization-code replay with exact and fresh credentials. CI runs those own-project security lanes and the malicious Company explicitly, with `--require-supported` to reject silently skipped cells. print-with-poppy's adapter is back at `b340741`, the first other project on the 28 October text. In Node the agent's image reads pages with `html-rewriter-wasm` for Workers' `HTMLRewriter` (`interop/impls/pda-agent/html-rewriter.ts`). `interop/impls/shared/mock-hooks.ts` is the one copy of the mock's hooks, shared by the mock's adapter (`interop/impls/pda-mock`) and `test/hypothesis/launcher.ts`. A failure that's upstream's or the spec's goes in `interop/known-failures.json` (`*` matches any agent, Company or scenario) with a reason. Interop-only behaviour (fault injection, the mock's `company.interop.test` placement) lives in the adapters, never in `src/`.
- No auth bypass anywhere, including tests and local dev.
- Log only through `src/log.ts`: add fields to the event of the unit you are in (`currentEvent()`, `reportError`), never a `console` call (`test/log.test.ts` fails on one anywhere else in `src/`). Never log text anyone said, tool arguments, tokens, keys, codes, emails or URLs with queries; the spec's Observability section lists the fields. An error that may carry a Company's words (`PoppyError`, `DiscoveryError`, marked `ForeignText`) is logged by class and code only, never its message. A field takes a value only from one of `src/log.ts`'s constructors (a raw `string` is a type error, and `test/log-types.ts` checks it under typecheck); don't cast to `Safe`, add a constructor.

Commands (Node 24, the LTS line in `.nvmrc`; `package.json` engines say `>=24`, CI and our interop images use 24):

- Validator CLI: `npm run validate -- <domain | url | file>`
- Docs check: included in `npm test`, reusing that run's discovered names. `npm run check:docs` independently discovers names for docs-only checks. Existence does not prove behavioral coverage.
- Dependency check: `npm run deps:check` runs `npm outdated` (information only) and `npm audit` of production and dev, and fails only at high or above; `.github/workflows/deps.yml` runs it on the 1st of each month and writes the report to the job summary. Report only: no Dependabot, no automatic pull requests, by the owner's choice.
- Spec snapshot: `node scripts/spec-snapshot.mjs` reports which pages of personalagentprotocol.org differ from the newest copy in `spec/`, and `--save` stores a new dated one (local only, not CI; `spec/grounding.md` ties our claims to the stored text)
- Spec pin: `npm run check:spec` checks the pinned snapshot's hashes (`spec/upstream.json`, the reviewed 29 October site text; its restored browser rule has no upstream commit yet) and that `spec/requirements-0.3.json` has a disposition for each of the changelog's 0.3 entries, in order; `npm run spec:drift` compares the pin with the live site, and `npm run spec:docs` regenerates the ledger table in `docs/poppy-0.3-upgrade.md`
- Tests: `npm test` runs five suites (Workers, durability, page, interop, properties); the spec's "Testing and conformance" table explains each; `scripts/test-projects.mjs` is the executable project list. Only `test/durability/` may reset every Durable Object. Nothing calls the network: the model, Anthropic, OpenAI, Google, GitHub, Companies, the open web and Browser Run are faked.
- Interop grid: `npm run interop -- [--agents pda] [--companies lenient-company] [--scenarios D,SD]` (Docker; `interop/README.md`, spec `docs/interop-spec.md`). Results go to `interop/results/` (gitignored).
- Property tests: `npm run test:properties`. Each property runs Hegel's default 100 cases; the full local suite takes minutes, with machine-dependent timings; a deep run is local only, never in CI: `HEGEL_CASES=5000 npm run test:properties`. Hegel keeps failing examples in `.hegel/` (gitignored). Write them with the Hegel skill (`.claude/skills/hegel/`) and check them against `hegel-review`; a failing property is never weakened, only fixed in the code or, with a written reason, in the test.
- Hypothesis (local only: not in `npm test` or CI): `npm run test:hypothesis` runs `test/hypothesis/`, an independent Poppy 0.3 client in Python driving five stateful, model-based tests of the mock Company on 127.0.0.1 (needs `uv`; no Docker). Add `-- --hypothesis-profile=deep` for a long run. Dependencies are pinned in its `uv.lock`.
- Approval process crashes: `npm run check:approval-crashes -- --output /tmp/approval-crashes.json` kills the PDA/workerd process group at four boundaries each for OpenAPI and MCP while the Company and its request ledger survive; CI runs it separately from Vitest.
- Types: `npm run typecheck`; regenerate `env.d.ts` with `npm run types` after changing `wrangler.jsonc`
- Deploy: `npm run deploy`. Who the deployment is for (`OWNERS`, the allowlists, `PUBLIC_ORIGIN`, `POPPY_LOGO_URI`) is never committed: `wrangler.jsonc` holds empty placeholders and the deployer's values live in the untracked `deployment.local.json` (shape in `deployment.example.json`); the deploy stops if the build is unconfigured. `test/template.test.ts` scans every committed file but docs (code, `test/`, `interop/`, `.github/`, root config; `*.md` may name the live host) and fails if an identity or origin from `deployment.local.json` (when present), a non-example email or another workers.dev host enters it; it names nobody itself.
- Pre-push hook: `.githooks/pre-push` runs only typecheck; CI runs the tests and the docs check. Enable once per clone with `git config core.hooksPath .githooks`; don't add an npm `prepare` script for it (CI would run it).
- Docker base images are pinned by digest (`FROM image:tag@sha256:…`); `interop/README.md` says how to move a pin.
- Readings: a choice where the draft is ambiguous goes in `docs/readings.md` (strict where it's security-relevant, lenient where it's cosmetic) and in the adapter's declared `readings`. Interop findings that may be someone else's vulnerability follow `SECURITY.md`: their maintainers first, privately; nothing is posted to another project without the owner's approval.
