# Durable Personal Agent

The design is `durable-personal-agent-spec.md`; read it before changing anything. v0 (milestone 1) is what is built, with the spec's Option B sign-in (Google and GitHub OAuth in the Worker) instead of Cloudflare Access: one Worker, one `PersonalAgent` Durable Object per signed-in identity running Pi through `PiHarness`, Claude Opus 5.5 through AI Gateway. The Poppy (Personal Agent Protocol) client is in `src/poppy/`; Appendix A of the spec maps every requirement to the code and the check that covers it.

- `src/protocol.ts`, `src/sockets.ts`, `src/view.ts` and `src/transcript.ts` are copied unchanged from Cloudflare's Pi example (`cloudflare/agents`, `examples/next/harnesses/pi`, commit `48d9c36`). Do not edit them; re-sync them from upstream instead.
- Our code: `src/index.ts` (Worker routes), `src/oauth.ts` (Google and GitHub sign-in), `src/session.ts` (signed session cookie, agent naming), `src/allowlist.ts` (who may sign in, from the `ALLOWLIST` var), `src/config.ts` (vars and secrets, no defaults), `src/agent.ts` (the Durable Object), `src/poppy/` (the Poppy client, its Lifecycle capability and tools), `src/poppy/activity.ts` (the Activity frame, from the agent's own tables, never secrets), `src/ui/` (the page: shell and routing, chat, transcript, `tool-line.ts`, Activity, Companies, Settings), `src/poppy-ui.tsx` (Poppy cards, the needs-you tray, receipts, the Direct Conversation sheet), `src/validator/` (the discovery document validator: no Worker APIs, so it also runs as the CLI in `scripts/poppy-validate.ts`; a new message needs a fixture in `test/validator.test.ts`, whose last test checks every message has one).
- Poppy tests run against the strict mock Company in `test/mock-company/`; every Poppy test asserts it recorded no violations. An `afterEach` enforces that; a test that breaks the protocol on purpose declares `expectViolations`. A new Poppy feature needs a test and, where the protocol has a MUST, a mock check with an id in `test/mock-company/violations.ts` and a `TAMPERS` row in `test/mock-company.test.ts` (a catalog test enforces both). The page started as the example's; `src/client.tsx` now holds only the signed-out page and mounts `src/ui/`, and `src/use-pi-session.ts` folds the socket's frames.
- `interop/` is the M×N interop harness: a Node runner, a recording proxy, scenarios as data, and adapters for our agent (`interop/impls/dpa-agent`, src/poppy in Node with node:sqlite, no model) and our mock Company (`interop/impls/dpa-mock`). Interop-only behaviour (fault injection, the mock's `company.interop.test` placement) lives in the adapters, never in `src/`.
- No auth bypass anywhere, including tests and local dev.

Commands:

- Validator CLI: `npm run validate -- <domain | url | file>`
- Docs check: `npm run check:docs` (every test Appendix A names exists; CI runs it with typecheck and tests)
- Tests: `npm test` runs four suites: Workers (`test/vitest.config.ts`), durability (`test/durability/`, its own runtime, the only place a test may reset every Durable Object), page (`test/ui/`, happy-dom) and interop (`interop/vitest.config.ts`, Node: the harness's own pieces). (Vitest in the Workers runtime; the model is pi-ai's faux provider, Google and GitHub are faked in `test/fake-providers.ts` (they check PKCE and can refuse), Companies by `test/mock-company/`)
- Interop grid: `npm run interop -- [--agents dpa] [--companies dpa-mock] [--scenarios D,SD]` (Docker; `interop/README.md`, spec `docs/interop-spec.md`). Results go to `interop/results/` (gitignored). After changing a validator fixture or a mock `TAMPERS` row, regenerate the vectors with `npm run interop:vectors`; a test fails while `interop/vectors/` is stale.
- Types: `npm run typecheck`; regenerate `env.d.ts` with `npm run types` after changing `wrangler.jsonc`
- Deploy: `npm run deploy`
